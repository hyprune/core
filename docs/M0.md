# M0 implementation and acceptance record

Date: 2026-10-07. Core is new code in `hyprune/core`, branch `main`. Nothing was
pushed. Prototype consultation was limited to C++ Hyprland API usage and the
nested harness; no prototype assets or source files were copied.

Reference contracts: docs `e638fb6` (RFC-0002/0003/0004 plus surface/interaction
RFCs); schema `96dad32`, world format `0.1`, IPC `0.1`. Both remain proposed
contracts pending owner review. The pinned world/common schemas are embedded for
offline validation. The independent schema CLI also checks generated content and
captured real IPC responses/notifications.

## What is running

- `hyprune-core.so`, C++23, exact ABI guard against Hyprland 0.56.2 on this machine.
- `hypruned`, separate public IPC/grant process, connected over an inherited private
  socketpair. No compositor pointers or pixels cross the bridge.
- Original procedural CC0 atrium, generated from source. glTF geometry, safe
  package paths, transformed static collision nodes, validated spawn, padded UV1
  irradiance atlas, linear/sRGB decoding, HDR world target, 4× MSAA and one tone map.
- Fixed 60 Hz walk/fly strategies with capped catch-up; capsule collision and jump.
- Live floating root-window textures, a matching picking ray, real pointer button
  dispatch, keyboard focus/typing, basic wheel forwarding, pressed-target capture
  and cancellation. Compositor shortcuts and F12 desktop escape take priority.
- Framed/authenticated IPC hello/ping, state subscription/resync, installed-world
  load, movement selection, surface focus and runtime exit. Failed world loads
  preserve the current world. Mutations acknowledge committed revisions.
- PID/start-time/config/socket-verified nested controller, full-lifetime flock,
  automated smoke/failure tests, and a checked H.264 gallery recording.

The module map and build/run commands are in [README](../README.md). Source, test
and lifecycle rules are in [CONTRIBUTING](../CONTRIBUTING.md).

The `core` and `ipc` executables also pass a Debug build with AddressSanitizer
and UndefinedBehaviorSanitizer. The final live wire capture passed independent
schema validation for 11 responses and 29 notifications; the video run separately
validated 200 responses.

`dev/nested/run.sh` passes on Hyprland 0.56.2:

1. Load plugin, start helper, negotiate IPC 0.1 and load the installed fixture.
2. Open two actual Kitty terminals, toggle HEADLESS-1 into the world, observe
   rendered frames with no plugin render errors, save a screenshot.
3. Hold/release W through a virtual Wayland keyboard; verify camera displacement
   of about 2.4 m. Ray-pick and click a terminal through a virtual Wayland pointer.
4. Type a shell command into that terminal and verify the resulting marker file.
5. Receive state deltas, return to desktop, reject an invalid world reload, switch
   fly/walk modes and reject anonymous state access.
6. Keep captured windows live on a hidden workspace; count real wl_surface commits
   and reject hidden-workspace keyboard focus with -32007.
7. Kill only this nested compositor's helper. Desktop mode is restored well within
   the one-second limit (53 ms measured in the recorded acceptance run).
8. Three fresh plugin mappings load, enter world mode, unload while active and
   reload without compositor crashes or stale pass callbacks.

The controller refuses commands after the session ends; no command is redirected
to the outer session. Expected invalid-world errors and ordinary nested XKB
warnings are not treated as compositor crashes.

## Deliberate scope differences and remaining limits

- The user's M0 request includes live surfaces/walking; RFC-0002 stages much of
  that at M1/M2. These are implemented here as a narrow developer slice, not a
  claim of full M1 or shell conformance.
- RFC-0003 does not define `camera.get`, `camera.set`, `surfaces.list` or `ui.open`.
  Adding them to `0.1` would violate its exact-version contract. Camera/surface
  reads are in snapshots; local Lua camera diagnostics/teleport support testing.
  `ui.open` and shell leases require an agreed shell contract and are not exposed.
- The helper owns wire IPC/grants and revisions, but package discovery is a trusted
  installed-directory configuration and decoding/validation lives in a plugin CPU
  worker. There is no full package registry, persistence or shell supervisor yet.
- Launch credentials are one-use, expire after 30 seconds and come from an
  inherited FD. The nested supervisor seeds them. Interactive grant issuance,
  policy approval, revocation and extension sandboxing remain unimplemented.
- GPU world upload is atomic but not incrementally time-budgeted. Hard command
  deadline behavior during a worst-case final GPU upload remains unverified. World CPU/GPU
  data is bounded; M0 collision is capped at 20,000 triangles. A simple static
  capsule collider keeps the fixture reproducible and avoids a large Jolt build;
  a BVH/Jolt adapter is the next step for large scenes, slopes/stairs and bodies.
- Root 2D textures avoid recursive compositor snapshot rendering. Full surface-tree
  capture, popups, external textures, crops/transforms and comprehensive DMA-BUF/
  explicit-sync compatibility need the M1 adapter. M0 omits unsupported sources.
  Capture leases are bounded to 16 windows and a 256 MiB texture estimate.
- Surface placement is an automatic development layout; world anchors, zones,
  navigation, positional audio and user bindings are not active runtime features.
  Unsupported required extensions reject activation. Full PBR/normal maps,
  transparent glTF materials, HDR/output color management and rotated outputs are
  not rendering guarantees.
- The minimal renderer preserves SDR application colors through an explicit
  bypass of the world tone curve. It does not yet implement the compositor's full
  source/output color-management and premultiplied-alpha contract.
- The nested compositor requests a 1600×900 window. Its floating state and final
  window size belong to the outer compositor. We deliberately did not alter the
  owner's real session to enforce them; the test/record output is 1920×1080.
- Native cursor visibility is untouched. No dedicated DRM/hardware-cursor,
  session-lock, output hot-unplug, VRAM saturation, hostile parser fuzzing or
  arbitrary app/popup compatibility result is claimed. These remain required
  acceptance work before recommending a live-session install.

## M1 next steps

1. Complete daemon package/grant supervision, bridge cancellation and bounded
   incremental GPU staging; add slow-consumer/revocation/deadline conformance.
2. Implement capture geometry generations, explicit synchronization, popup/child
   hit testing, full drag cancellation and source/output color transforms.
3. Integrate shell.claim/release/overlay and agree on the requested camera/UI
   methods in a new protocol revision, with shared schema fixtures.
4. Add anchor binding/persistence and supported world metadata; replace the
   brute-force collider behind its interface when realistic scene budgets demand it.
5. Exercise lock/hotplug/capture pressure and dedicated DRM cursor configurations
   in a disposable test session, followed by measured frame/upload/capture budgets.
