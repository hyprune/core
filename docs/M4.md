# M4 phase 1: HUD telemetry and optional runtime offload

The default renderer remains in-process on the compositor's GPU. Offload defaults
to **off**. IPC 0.10 adds the unified Performance contract; IPC 0.9 added the HUD
streams and rebindable `hud.cycle` action (default **5**, replacing reserved tool
slot 5).

## HUD contract

`hud.subscribe` opts into frame statistics at at most 4 Hz, pose/heading at at
most 30 Hz, zone enter/exit (world and home display names), and tool/subtype
changes. Unsubscribed clients receive none of these streams; slow consumers
drop obsolete telemetry. `ui.hud.cycle` goes only to the verified shell owning
the bound HUD lease. Holding 5 emits once and does not change tools. Generated
keymap documentation, canonical schema, SDK types and RFC-0008 are updated.
The frozen five-entry legacy tool descriptor remains compatible with older
shells, while only slots 1–4 are selectable tools.

## Hot switching and isolation

Performance → Offload starts a renderer child supervised by `hypruned`. Intel
keeps drawing while the child loads and warms. A complete, fence-ready frame
with matching generation and pose can replace the opaque world colour. Native
window buffers, glass, markers and prompts stay in-process, using reconstructed
world depth and the displayed frame's camera. Turning off, worker failure,
expired frames or policy withdrawal selects the prepared local renderer. Input,
the loaded world and Hyprland continue without a restart or reload.

The transport uses two Vulkan LINEAR DMA-BUF slots and explicit fences; the
consumer never waits synchronously for the worker's GPU. Frames older than
50 ms are rejected. The worker has a renewable 500 ms watchdog lease, parent
death protection, inherited descriptor cleanup, Landlock filesystem restrictions
and seccomp restrictions. Unsupported interop, sandbox or telemetry fails back
to local rendering. A failed worker stays off until an explicit off/on retry.

USB-C, battery and limited AC disable `auto`; explicit `on` admits at most
50 W / 45 FPS. Qualified full AC (advertised ≥150 W, no battery discharge)
admits at most 80 W / 60 FPS. The configurable power budget is a monitored
software ceiling, **not a privileged hardware power-limit guarantee**. Unknown
supplies fail closed. NVML samples must remain fresh and below the admitted
budget and 75 °C. The monitoring handle is released when the child stops.

`graphics.get/set` exposes requested and effective values, active renderer,
power draw/profile/cap, admitted FPS, preset/Custom, scale bounds and all existing
effect controls. Costs are GPU timer measurements. Effects sharing a shading
pass have a labelled shared cost and a null exclusive cost; unavailable costs
are null. F3 shows renderer, worker FPS, world/transfer/local-depth costs and
power. See [GRAPHICS.md](GRAPHICS.md) and RFC-0009's phase 1 amendment.

## Automated validation

Every compositor run used `flock /tmp/worldshell-nested.lock`; hardware runs also
used the independent AC/50 W/75 °C/55-second watchdog. No live session was
controlled. Evidence is in [evidence/offload/](evidence/offload/), including
compressed canonical IPC transcripts and the actual Performance menu screenshot.

| Check | Result |
| --- | --- |
| Core build and CTest | 10/10 pass, including transport, policy, sandbox, watchdog and native composition |
| Live tooling unit tests | 10/10 pass; no live invocation |
| Canonical IPC 0.10 schema / SDK | 92 schema checks; SDK 55 pass, 2 intentional skips |
| HUD nested acceptance | Scoped 5 action/rebind, subscriptions, zone and subtype changes, stream rate limits pass |
| Repeated off/on, movement and window carry | Pass at 1080p and native 4K |
| Worker killed during carry; explicit retry | Local fallback preserves the active world and carry; retry passes |
| Actual shell Performance dropdown | IPC 0.10 on/off, same world, populated costs, no QML errors |
| Native 4K, USB-C profile | 44.96–45.03 worker FPS; 96.7–100% offload samples; peak 32.78 W |
| 1080p recorded run | All sampled intervals 100% offload; peak 29.27 W |

Native 4K samples measured approximately 2.56–3.15 ms worker render GPU time
plus 1.29–1.91 ms transfer GPU time. Native composition still runs on Intel.
Worker FPS and compositor/output FPS are distinct. Full mains 60 FPS and battery
operation were tested through fake policy providers, **not physically qualified**.
Recording full 4K with software encoding caused transient stale-frame fallback
(about 69% offload samples in its carry interval); the freshness guard stayed
enabled. The final 1080p demo passed, and an encoded-frame black scan found no
black intervals. A recorded nested test is not a hardware-cursor live test.

Phase 1 supports compatible NVIDIA GLES/Vulkan LINEAR transport, outputs up to
3840×2160 and Linux x86-64 with Landlock ABI ≥3. Edited world-node transforms
select local rendering; ordinary window carry remains supported. Local rendering
is the fallback on other configurations. No new cursor transitions were added;
the supervised checklist is extended in [M3B.md](M3B.md).

Reproduce, from core:

```sh
cmake --build build -j2
ctest --test-dir build --output-on-failure
flock /tmp/worldshell-nested.lock python3 dev/nested/offload-power.py /tmp/offload-power.json python3 dev/nested/offload_acceptance.py
HYPRUNE_NESTED_4K=1 flock /tmp/worldshell-nested.lock python3 dev/nested/offload-power.py /tmp/offload-4k-power.json python3 dev/nested/offload_acceptance.py
flock /tmp/worldshell-nested.lock python3 dev/nested/offload-power.py /tmp/offload-menu-power.json python3 dev/nested/offload_menu.py
```

The 22.43-second demo and string-valued JSON sidecar are published at
`$HYPRUNE_VIDEO_DIR/hyprune-core-offload.mp4`
and `.json`. Encoding completed in `/tmp` before the final move.

## Supervised live retry

```sh
cd path/to/core   # your core checkout
dev/live/down
git -C ../shell pull --ff-only
dev/live/preflight
dev/live/up
```

The shell must include its IPC 0.10 Performance integration. The live toggle
prefers **Super+Shift+H**; `up` reports an alternative if that chord is occupied.
Hold TAB to open the Director, use 5 in-world to cycle HUD concepts, and choose
Performance → Offload → On for the optional worker. Offload starts off.

## Renderer interfaces for follow-on work

`Renderer::worldOnly` produces the worker's opaque display-encoded colour;
`externalWorldFbo` selects prepared external colour plus local depth/native
composition. `offload::Client` owns imports, fences, freshness and displayed pose;
the private bridge passes its channel and generation. `offload::Supervisor`
owns the child and power policy in `hypruned`. The public shell API remains
`graphics.get/set`.
