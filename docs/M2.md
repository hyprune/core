# Core M2 acceptance report

2026-10-07. Core 0.3.0, IPC 0.4, world format 0.3, Hyprland 0.56.2.
Core/docs/schema/shell changes are local commits. The owner's compositor was
never controlled; every nested run held `/tmp/worldshell-nested.lock`.

## Features and contract

Each area is one workspace home. It owns a primary whole-workspace wall, tool
mounts and data objects. Actual workspace IDs bind to author slots/areas. Stock
Hyprland focus-in/out preserves camera and app ownership. Workspace switches
travel within a world and warp across worlds. Pulled windows carry through the
world, snap to free mounts of their owning area, and receive native mouse clicks,
scroll, drag and text in place. Full anchor quaternions support tilted surfaces.
Bindings and class/title placement rules persist through the daemon's atomic
layout file; relaunch resolves a new surface ID to its saved home.

Collision recovery checks complete rectangles with triangle/OBB SAT, support rays
and a swept OBB. Thin obstacles between rays cannot tunnel. Mount approaches
push surfaces forward along their normal with a margin. Invalid placements
relocate to an owned free mount, a reserved area volume or safe recall, and emit
a notice. Recall all windows is available in IPC and the reference Director;
it preserves durable rules and includes live saved tools from other worlds.
Concurrent identical app/title matches use distinct temporary mounts rather than
rewriting each other's persistence. Data objects publish identity, pose and an
owned publisher-source binding for an extension/shell to present.

RFC-0004/0005 and schema `9dde810` add `areas`, anchor `mount` metadata,
`dataObjects`, `placementZones`, and `atmosphere`. IPC 0.4 adds mount bindings,
workspace focus, pull/place/return/recall, placement rules, data-object binding,
atmosphere and FOV. Its `mounts` and `presentation` state keys and change hints
are version-isolated; frozen 0.1–0.3 projections remain available. Details and
grants are in [CHANGES-FOR-SDK-AND-SHELL.md](CHANGES-FOR-SDK-AND-SHELL.md).

Lumen Reach's optional format 0.2 namespaces normalize to this contract without
rewriting packages. `freePlacementZones` is an array of IDs, separate from zone
objects. Author names and approach annotations are ignored in strict validation.
The four homes remain Sun Court/01, Array Hall/02, Rime Vault/03, Signal Rise/04.
`com.hyprune.lumen-reach.routes` validates feet-position nodes and bidirectional
width-bounded edges. A Director destination expands along the shortest graph
path, preserving exact ramp bends and landings; every movement step retains
capsule collision. Disconnected paths reject. Continuous ramps work, while
climbing discrete risers remains unsupported.

The renderer now supports glTF OPAQUE/MASK/BLEND with primitive sorting,
double-sided lighting, camera-relative exponential height fog, an unlit-art fog
exclusion, per-world sky/sun, emissive-strength HDR, normalized separable Gaussian
bloom, exposure and ACES/Reinhard/linear tone mapping. A CPU worker GGX-prefilters
an authored six-face environment or procedural sky into an HDR cubemap. Glossy
floors sample roughness-dependent mips. Apps bypass fog, exposure, tone mapping
and bloom. All touched GL state, including cube bindings, samplers and culling,
is restored. FOV is controlled through IPC.

High quality uses 128² probes, 4× MSAA and up to 8× anisotropy. Intel uses 64²
probes, 2× MSAA, up to 2× anisotropy and half-resolution bloom. Both tiers use
half-resolution bloom and no SSR. This is static environment reflection;
box-projected local probes and dynamic geometry reflections are not implemented.
Per-area atmosphere is deferred; live atmosphere edits support fog, exposure,
tone mapping and bloom. Sky/environment edits require package reload.

The real Lumen Reach package additionally loads and reaches its globe platform

## Reproduce and package capture hooks

```sh
python3 tests/fixtures/m2.py
cmake --build build -j4
ctest --test-dir build --output-on-failure
./dev/nested/run.sh --m2
./dev/nested/run.sh --m2 --record
HYPRUNE_M2_PACKAGE="$PWD/../worlds/dist/com.hyprune.lumen-reach" ./dev/nested/run.sh --m2 --serve
```

`run.sh` takes the lifetime flock itself. `HYPRUNE_M2_PACKAGE` copies the package
unchanged into the isolated world directory, loads it after fixture acceptance,
binds available areas and captures `m2-package.png` after the warp overlay clears.
`--serve` retains that verified nested session for authoring. `dev/hyprune-dev`
provides `m2`, `m2-smoke`, and `m2-record` aliases. M2 controller state is separate:

```sh
HYPRUNE_NESTED_STATE_DIR="$PWD/dev/nested/.m2-state" dev/nested/ctl.py shot /tmp/lumen-reach.png
```

The harness's authenticated `client` supports `workspace.bind`, `surface.pull`
and `surface.place` for live terminal staging; base anchors/area IDs come from
`state.mounts`. Do not reuse consumed tokens. New external clients need a fresh
launch grant. All compositor control must go through `ctl.py`, which verifies
PID start time, config, signature, Wayland socket and nested lock identity. Never
invoke `hyprctl` against the outer session. No local Blender work is involved.

## Lumen Reach workspace sampling follow-up

Imported client buffers can retain `GL_NEAREST_MIPMAP_LINEAR` filtering while
providing only level zero. Workspace composition previously used those native
texture parameters, sampling black even though the source contained visible
pixels and committed normally. Composition now owns a linear/clamp sampler,
released with its other GL resources. It never changes leased texture parameters;
`GLState` restores the prior sampler and active texture. No input, cursor or
compositor-render lifecycle change is involved.

The GPU regression reproduces missing-mipmap black sampling, verifies exact RGB
with the owned sampler, and checks native filtering and foreign GL state remain
unchanged. A disposable diagnostic build read back all four Lumen Reach workspace
FBOs under the lifetime nested lock: each contains live content, with complete
framebuffers and no GL error. GPU readback instrumentation is absent from the
normal plugin. See [readback evidence](evidence/m2-workspace-sampler.json).
The normal rebuilt plugin also passed a separate locked nested run: all four
primary walls were visually verified with live btop, all four tools remained
placed, and real terminal typing passed. See the
[Array Hall still](evidence/m2-workspace-sampler-array-hall.png).
The separate btop minimum-size warning requires a terminal of at least 80 columns
and 24 rows; the nested verification used 900×600 Home buffers.
