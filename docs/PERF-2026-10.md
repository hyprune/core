# Render performance, October 2026 (research note Part A)

Branch `perf/render-standard`. Standard techniques and proven libraries from
`docs/research/2026-10-proven-techniques.md` Part A, one measured commit each.
All runs are nested (`dev/nested/run.sh --perf`, which holds the nested lock);
the owner's live session was never touched.

## Method

- Scene: native 3840×2160 headless output (`HYPRUNE_NESTED_4K=1`), Mesa Intel
  PTL, a frozen copy of Lumen Reach 0.7.0 (`/tmp/hyprune-perf`, scene.bin SHA-256
  `d02909a7…`), quality Low/iGPU, offload off, dynamic resolution off, fixed
  internal scale, sharpen 0.35. A mounted workspace wall (Sun Court, terminal on
  workspace 10) and two terminals on authored anchors
  (`sun-court-slot-01-field-rig-01/02`).
- Poses: the four authored spawns (arrival, array hall, rime vault, signal
  rise) at eye height, yaw 0. 30 samples per pose; medians of the existing
  disjoint GPU timer queries and CPU timings.
- Fixed-scale comparisons use `HYPRUNE_CONTINUOUS_RENDER=1` (a frame every tick),
  because with render-on-demand a sparse frame runs at lower GPU clocks and
  costs more per frame. Builds are compared build-vs-build in alternating
  sessions (A, B, A, B; `HYPRUNE_NESTED_PLUGIN`), packages in alternating rounds
  in one compositor (`HYPRUNE_PERF_WORLD_B`, `HYPRUNE_PERF_ROUNDS`).
- The iGPU is shared with the owner's desktop, so absolute GPU ms drift by
  ±0.3–0.5 ms between sessions even for passes a change cannot affect. The
  upscale pass (fixed 4K bandwidth) is a same-frame clock proxy: where a change
  could only affect the world pass, the world/upscale ratio is reported too.
- Power: RAPL `energy_uj` is root-only on this machine. Idle cost is the
  nested compositor's share of render-engine cycles from its own DRM fdinfo
  (`drm-cycles-rcs`, xe driver), plus system-wide gt0 idle residency.
- Reproduce: `HYPRUNE_NESTED_4K=1 dev/nested/run.sh --perf`, then
  `dev/nested/perf_compare.py <report.json…>`. Reports land in
  `/tmp/hyprune-perf/results/<label>/report.json` with the stills.

### Notes per step

1. **Render on demand.** A world frame is keyed on all of its inputs (camera,
   output, drawn surfaces and client commit counters, overlays, prompts,
   editor lines, object transforms, graphics/atmosphere). Tick damages the
   output only when the key changed since the last *rendered* frame, so reused
   frames and late commits keep it rendering. Debug HUD (F3), loading,
   warps/fullscreen transitions, U captures, offload, replay and autodrive
   always render. A compositor repaint with an unchanged key re-presents the
   cached native frame (`timings.idleFrames`). `deliveredFPS` now drops while
   nothing changes; the shell Performance page should show "idle" rather than
   a low FPS when `idleFrames` grows and `renderedFrames` does not.
2. **Lightmap mips.** Lightmaps now use their glTF sampler, clamped (RFC-0004
   requires mip-safe gutters). A mipmapped filter opts in to trilinear
   irradiance, capped at LOD 2 (the bake pipeline's 4 px gutters). Lumen's
   lightmap samplers are LINEAR today, so shipped packages render unchanged.
   The worlds pipeline can opt in per group by writing LINEAR_MIPMAP_LINEAR
   for groups whose bake report says `supportedMipLevels >= 2` (not foliage).
   No schema change.
3. **Single colour upload.** One texture per image: sRGB for colour slots, raw
   for data slots, one sRGB copy plus a `EXT_texture_sRGB_decode` skip-decode
   sampler when an image is both (two copies without the extension).
   `world::gpuBytes()` is now the only estimate.
4. **Uniforms.** Material constants live in one std140 UBO per world; the
   normal matrix is computed on the CPU and only sent for edited objects;
   uniform locations are cached.
5. **Frustum culling.** Per-batch world AABB against the six planes of `vp`.
6. **Index buffers.** The loader keeps the flat triangle list for collision,
   picking and editing, and builds an indexed GPU copy with meshoptimizer
   (vertex remap, vertex-cache and fetch order; blended materials keep their
   triangle order). Lumen's export is barely indexed (748,764 indices over
   598,111 vertices), so the saving is small today. A gltfpack/glTF-Transform
   build step (Phase 3) is where indexed, quantised meshes pay off. The
   changed triangle order flips which face wins an existing coplanar overlap
   at the Sun Court roof edge (looks cleaner after; the worlds coplanar check
   should flag that geometry regardless).

## Phase 2: FSR 1

AMD FidelityFX FSR 1 (EASU + RCAS, MIT, `6ada5e1`) replaces the bilinear +
4-tap sharpen upscale when `upscaler` is `fsr1` and the world renders below
output size: bloom + tone map at internal resolution into perceptual RGBA8,
EASU to an output-sized intermediate, RCAS into the native target with the
same nearest internal-resolution depth as before (window occlusion and native
client pixels unchanged). `sharpen` 0..1 maps to RCAS 2..0 stops. The programs
need GLSL ES 3.1; on failure `timings.upscaler.error` is set and bilinear stays.

Selection is `HYPRUNE_UPSCALER=fsr1` (default `bilinear`) until the lead decides
the IPC 0.16 `upscaler` graphics setting (drafted; a new graphics key is a
contract change because `graphicsConfig` is closed).

| Scale | Upscaler | Upscale stage | Total GPU (4 poses, 2 runs) |
| --- | --- | --- | --- |
| 0.5 | bilinear + sharpen | 2.44 ms | 6.24 ms |
| 0.5 | FSR 1 | 5.30 ms | 8.47 ms |
| 0.375 | bilinear + sharpen | 2.69 ms | 5.72 ms |
| 0.375 | FSR 1 | 5.28 ms | 7.66 ms |

(Session clocks were lower than in Phase 1 runs, because the iGPU was shared
with other nested runs and the desktop; compare rows, not with Phase 1.)

Visual A/B (gallery `screenshots/core-perf-2026-10/phase2-fsr1-vs-bilinear-2026-10-09.png`):
at 0.375 the bilinear path turns thin geometry (dish wires, rails, stair edges)
into stair-stepped blocks and the sharpen exaggerates them; FSR 1 resolves them
as clean edges and sharpens world-rendered screen text. This is a core-side
cause of the "blocky" look at the scales Intel 4K actually runs. Low-resolution
sky textures remain an asset matter.

Recommendation: FSR 1 as the default on Medium and above, and opt-in on
Low/iGPU 4K, where its ≈2 ms costs about one dynamic-resolution step
(0.0625). Dynamic resolution absorbs it automatically either way.

## Phase 3: compressed and optimised assets (held branch `perf/compressed-assets`)

Core support for `KHR_texture_basisu` (KTX2, Basis Universal transcoder),
`EXT_meshopt_compression` and `KHR_mesh_quantization`, available to packages
declaring world format **0.7** (RFC-0004 amendment, schema `6250450`, SDK
`2a0742d`). Earlier formats reject these extensions.

Driver formats (Mesa 26.2, Intel PTL, GLES 3.2): BPTC, S3TC (+sRGB), RGTC and
ASTC LDR are advertised. Core picks BC7 > BC1/BC3 > ASTC 4×4 > RGBA, skipping ETC2
(core in ES 3, often emulated on desktop GPUs).

Test package: a `/tmp` copy of Lumen Reach 0.7.0. Material textures were
encoded with `basisu -uastc -mipmap -ktx2` (zstd; `-linear` for ORM,
`-normal_map` for normals) and added as `KHR_texture_basisu` in place; geometry
went through `gltf-transform meshopt --quantize-position 16 --quantize-texcoord 16`.
Lightmaps stay PNG. glTF-Transform drops textures no material references, and
Hyprune lightmaps are referenced only by world.json, so the converter re-appends
them at their original (trailing) indices. gltfpack was rejected because it
renumbers nodes and materials.
